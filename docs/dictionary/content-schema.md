# Формат редакторських записів словника

Це формат підготовленого словникового контенту для імпортера T20. Чинний груповий імпортер `rank,target,source,transcription` його ще не підтримує; новий набір не підкладати до старого імпортера.

## Поля леми

| Поле | Вміст |
|---|---|
| `id` | Стабільний ID запису, не змінюється після перевпорядкування. |
| `lemma_pl` | Польська словникова форма. Рахується як одна лема. |
| `part_of_speech` | Частина мови / POS-тег; потрібен для неоднозначних форм. |
| `gender` | Польський граматичний рід (`m`, `f`, `n`) для іменників; `pl` — окрема позначка множинної словникової форми за джерелом, а не вигаданий рід. У клієнті відображати як «мн.». |
| `gender_pair_id` | Спільний ID для потрібних чоловічої/жіночої назв людей або посад; обидві форми рахуються окремими лемами. |
| `aspect_pair_id` | Спільний ID для лем доконаного/недоконаного виду; обидві леми залишаються окремими записами. |
| `translation_uk` | Канонічний український відповідник і прийнятні варіанти, окремі через `;`. |
| `accepted_answers_pl` | Прийняті польські відповіді через `;`; у поточному наборі — сама лема. Нові варіанти потребують окремого джерельного підтвердження. |
| `pronunciation_uk` | Наближена підказка українськими літерами; позначати наголос, де потрібно. |
| `domain` | `everyday` або `legalization`. Кожна лема належить рівно до однієї квоти. |
| `legalization_stage` | Для домену легалізації: `appointment`, `application`, `supplement`, `status`, `decision` або `pickup`. |
| `topic` | Напрям на кшталт `home`, `food`, `transport`, `health`, `work`, `appointment`, `application`, `documents`, `status`, `decision`. |
| `frequency_rank` | Корпусний ранг для побутових слів (KWJP після перевірки); порожній для записів, ранжованих за спеціальною корисністю. |
| `utility_rank` | Ранг практичної корисності для легалізаційної лексики. |
| `show_context_before` | Якщо значення неоднозначне, показати `example_uk` до відповіді; польський варіант відкривається після відповіді. |
| `example_pl` | Одне коротке природне польське речення. Воно показує конкретне значення леми. |
| `example_uk` | Природний український переклад польського прикладу. |
| `validation_status` | `draft`, `needs_review` або `approved`. До виробничого словника потрапляють лише схвалені записи. |
| `validation_sources` | ID доказу з evidence.jsonl: сторінка Wikisłownik, конкретне значення, пов’язаний український переклад, IPA та SHA-256 джерельного рядка. Частотність — KWJP. Додаткові джерела потрібні для виправлень, яких базове джерело не підтверджує. |
| `reviewed_by` | Спосіб редакторської перевірки; LLM-редактуру явно позначати, не видавати за незалежну перевірку людиною. |
| `review_note` | Необов’язкове уточнення для редактора, не показувати в картці без потреби. |

## Поля фрази або мінідіалогу

Фрази й мінідіалоги зберігати окремо від таблиці лем, бо вони не рахуються до словникової цілі (зараз робочий орієнтир — 2 000 лем). У MVP це короткі двомовні картки для читання й повторення готових фраз, без рольової взаємодії. Кожен запис має містити польський текст, український переклад, етап легалізаційної справи та перевірений контекст уживання.

## Правила приймання

1. Не створювати окремі леми для граматичних форм одного слова. Часті форми подавати у прикладах. Дієслова доконаного й недоконаного виду — окремі пов’язані леми; вводити їх окремо за частотністю.
2. Потрібні чоловічі й жіночі назви людей/посад зберігати як окремі пов’язані леми; не рахувати їх як перекладні варіанти одного запису.
3. Не дублювати однакову лему в двох доменних квотах; змістити її до основного практичного домену, а друге значення показати прикладом.
4. Зберігати кілька перекладів лише тоді, коли це справді навчальні відповідники; стандартний український відповідник подавати першим, поширений у Польщі місцевий варіант — додатковим. Контекст прикладу має показати потрібне значення. Для локальних реалій, що є словосполученнями, а не окремими лемами (наприклад, `karta pobytu`), зберігати відповідник у `local-equivalents.md`, не переносити значення всього словосполучення в переклад окремої леми.
5. У прикладах про користувача спершу вживати природну нейтральну конструкцію; якщо це неможливо, показувати чоловічий і жіночий варіанти. Вимову писати українськими літерами наближено; позначати наголос лише коли він відхиляється від типового або знак потрібен, щоб уникнути плутанини. Якщо джерела наводять кілька вимов, показувати одну нормативну й найуживанішу; інші додавати лише коли це важливо для розуміння.
6. Застосунковий CSV зараз має лише `rank,target,source,transcription`, а імпортер не підтримує повну редакторську схему й коректне розбирання CSV із комами в полях. Файл `course.csv` зберігати в `docs/dictionary/` до оновлення імпортера T20; не змішувати дві схеми в одній папці імпорту.

## Статус перевірки

Рішення користувача від 2026-11-01 дозволяє LLM-редактуру з перевіркою за джерелами та журналом доказів. Воно замінює попередню заборону LLM у підготовці контенту. LLM у самому застосунку, заняттях і runtime-звірці reports до обсягу не додається.

Погоджений користувачем стандарт від 2026-11-01: джерельна звірка Wikisłownik + LLM-редактура. Для `approved` потрібні:

1. Однословна польська лема, визначена частина мови й рід іменника. Словниковий запис не має бути лише граматичною формою, скороченням, власною назвою чи непридатним стилістичним значенням.
2. Український відповідник, пов’язаний у джерелі саме з вибраним значенням. Наявність написання на сторінці не є підтвердженням перекладу. Хибні друзі, розірвані переклади й невідповідність частотному побутовому значенню відсіюються редактором.
3. IPA для потрібної форми та наближена українська підказка вимови, звірена редактором із IPA. Підказка не замінює фонетичної транскрипції й не є аудіооцінюванням.
4. Самостійно укладений короткий польський приклад і його український переклад; редактор перевіряє узгодження, природність і відповідність тому самому значенню, зіставляючи з джерельним ужитком. Приклад джерела дослівно не переноситься.
5. Збережені редакторське рішення, сторінка/значення джерела, атрибуція та контрольні суми. `reviewed_by` явно вказує LLM-редактуру. Це не незалежна перевірка носієм мови, не повна нормативна звірка всіх записів із WSJP PAN і не перевірка всіх речень у незалежному корпусі.
6. Технічний валідатор підтверджує повноту, унікальність, мови полів, зв’язки з доказами й кількість. Він не може самостійно ухвалити семантичне рішення редактора.

Wikisłownik є джерельною базою цього випуску; його структуровані дані також можуть містити помилки. При сумніві щодо перекладу, нормативності чи спеціального терміна потрібне додаткове джерело (наприклад WSJP PAN або офіційний двомовний матеріал); інакше запис відкладається, а не виправляється без доказу. Неперевірені записи лишаються у `review-queue.csv` поза курсом.

Ціль пілоту — 2 000 унікальних схвалених лем без обов’язкового розподілу 1 600/400. Частотний порядок не гарантує коректної лематизації, тому джерельні кандидати проходять редакторський відбір. Майбутні зміни за reports потребують такої самої перевірки й можливості відкату.

Користувач окремо прийняв цей стандарт замість попередньої вимоги звірки кожної леми з WSJP PAN та незалежної корпусної перевірки кожного прикладу. Спосіб перевірки завжди вказується явно; додаткові нормативні й корпусні перевірки не приписуються набору, якщо їх не проводили.
