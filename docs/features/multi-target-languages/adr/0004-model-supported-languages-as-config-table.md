# 0004 — Моделювати набір підтримуваних мов як конфіг-таблицю, а не enum у коді

- **Status:** Accepted
- **Date:** 2026-11-04
- **Deciders:** Viacheslav Melnichenko (Tech Lead), архітектурна сесія

## Context

Код сьогодні хардкодить `"pl"`/`"uk"`: `SearchFormsProjection` додає форми з `Lang=="pl"`, `PolishMorphologyImporter` цілком польсько-специфічний, перевірки леми фільтрують `form.Lang=="pl"` (brownfield-скан). Водночас `search_forms.Lang`/`morph_forms.Lang` уже мово-свідомі (`VARCHAR(2)`). Стовп розширюваності фічі (sad §1, quality goal №2) — додати мову як конфіг + контент, без зміни коду тренера. Питання: де живе набір підтримуваних мов і їхні правила.

## Decision drivers

- Quality goal №2 — розширюваність: нова мова без зміни коду тренера (sad §1; Approach C).
- Наявний мово-свідомий субстрат пошуку/форм (`search_forms.Lang`, `morph_forms.Lang`) — перевикористати, не дублювати.
- Відкриті per-language правила (OQ-5 нормалізація/форми, OQ-6 local-equivalents, OQ-8 транскрипція) — мають місце для прив'язки без розповзання по коду.
- Конвенція: DB як «тупе сховище», бізнес-правила в коді (sad §2; `.claude/rules/migrations.md`).

## Considered options

1. **Таблиця `target_languages` + per-language конфіг** — рядок на мову (код, увімкненість, прапорці правил); код тренера читає конфіг і застосовує відповідні правила.
2. **Enum мов у коді** — набір мов фіксований у коді; кожна нова мова = зміна enum + деплой.

## Decision outcome

**Chosen:** Option 1. Нова мова стає рядком даних + контентом; увімкнення/вимкнення мови — зміна даних, а не деплой. Конфіг дає точку прив'язки для per-language рішень (OQ-5/6/8), а наявний `search_forms.Lang`/`morph_forms.Lang` перевикористовується зі зняттям хардкоду `"pl"`. Option 2 примушувала б деплой на кожну мову й розсівала б мово-специфічні гілки по коду, що суперечить quality goal №2.

## Consequences

**Positive**
- Нова мова = рядок у `target_languages` + контент; увімкнення без деплою.
- Єдина точка для per-language правил — вузол рішень для OQ-5/OQ-6/OQ-8.
- Узагальнення `SearchFormsProjection`/морфологічного імпортера до конфігурованих знімає хардкод `"pl"`.

**Negative**
- Самого рядка конфігу недостатньо: мова «увімкнена» лише коли є схвалений контент і (для AC-08) підтверджений каркас нормалізації/форм — узгодженість даних і коду треба стерегти (AC-02, OQ-5).
- Морфологічний імпортер усе одно потребує per-language джерела/лексикону (OQ-7) — конфіг описує, але не постачає їх.

**Neutral**
- Правила DB-as-dumb-storage зберігаються: конфіг описує прапорці, рішення ухвалює код.
- Конкретні бізнес-прапорці (бізнес-DEFAULT) не кладуться в DB-DEFAULT — лишаються в коді (конвенція міграцій).
