# PRD — multi-target-languages

> **Inputs (required):** [idea-brief](./idea-brief.md) · [CONTEXT](../../../CONTEXT.md) (єдиний доменний словник проєкту в корені репозиторію)
> **Reference module:** `docs/features/personal-trainer-mvp` — [PRD](../personal-trainer-mvp/PRD.md) і [data-model](../personal-trainer-mvp/data-model.md): модель заняття, вправи пригадування, word status, daily new words limit, base course, пошуку й черги content reports.
> **External context channels used:** Project docs: [PRD personal-trainer-mvp](../personal-trainer-mvp/PRD.md), [PRD unlimited-learning](../unlimited-learning/PRD.md) (узгодження термінів прогресу); контент-метод: [docs/dictionary/README.md](../../dictionary/README.md), [local-equivalents](../../dictionary/local-equivalents.md).

## 1. Context

Тренер сьогодні навчає лише польської: наявна модель словника й прогресу прив'язана до однієї мови, а весь прогрес learner (word status, повторення, daily new words limit) рахується для неї єдиної. Пілотні учні — передусім україномовні дорослі, чия реальна ціль не завжди польська, — просять інші мови: англійську, німецьку, нідерландську. Цим learner тренер сьогодні не має що запропонувати, і вони йдуть до масових застосунків із генеричним контентом ([idea-brief §2](./idea-brief.md), §3).

Пілот наближається й тримає фокус на польському MVP, але запити на інші мови від пілотних учнів уже надходять. Розширення узгоджено одразу після пілоту, поки інтерес свіжий і поки тренер ще легко узагальнити під кілька мов ([idea-brief §4](./idea-brief.md)).

Обраний вектор ([idea-brief §13](./idea-brief.md#13-recommendation), Approach C — «Many Languages, One Trainer»): узагальнити тренер до кількох target languages за перевикористовним каркасом на кожну мову. Кожна мова дістає власний контент, вимову, приклади, форми й місцеві відповідники там, де вони є; прогрес learner рахується окремо для кожної мови; source language лишається українською. Нові мови додаються тим самим шляхом, що й три перші, без перебудови тренера.

- Трасування reference-патернів: наявні заняття, вправа пригадування, картка слова, пошук за формами й черга content reports побудовані навколо однієї мови; пошук за формами вже має мовний вимір, а підготовка контенту кожної мови — окремий набір схвалених лем. Контент готується тим самим методом підготовки редакторського словника, що дав польський випуск (джерело частотності + редакторська звірка з довідковими джерелами, [docs/dictionary/README.md](../../dictionary/README.md)); для англійської, німецької та нідерландської застосовується його аналог на кожну мову — відповідне джерело частотності, джерело вимови й довідкові джерела звірки. Ролі лишаються ті, що в CONTEXT: learner і content editor; нових ролей фіча не додає.

## 2. Goals

- Learner обирає, яку мову вивчати (польська, англійська, німецька, нідерландська), і може вести кілька мов, повертаючись до кожної ([idea-brief §13](./idea-brief.md#13-recommendation)).
- Прогрес кожної мови окремий: word status, повторення й daily new words limit однієї мови не змішуються з іншою.
- Кожна мова має контент і механіки, властиві їй (вимова, приклади, форми, прийняті відповіді), підготовлені тим самим методом, що й польська.

## 3. Non-goals

- Нові source languages та переклад інтерфейсу застосунку іншими мовами — source лишається українською ([idea-brief §6](./idea-brief.md#6-competitive-analysis)).
- Повна матриця пар «вивчаю X — пояснення Y» — поза наміром фічі ([idea-brief §6](./idea-brief.md)).
- Міжмовні підказки (вивчати нідерландську через відому англійську) — out of scope ([idea-brief §6](./idea-brief.md)).
- Автоматичне перенесення прогресу між мовами — кожна мова починається з чистого обліку ([idea-brief §6](./idea-brief.md)).
- Готовий зовнішній курований контент від постачальників — кожна мова готується власним методом редакторського словника ([idea-brief §5](./idea-brief.md)).
- Тест рівня чи розподіл за рівнями на старті нової мови — за рішенням проєкту всі learner починають з однакових частотних слів (CONTEXT, Out of scope).

## 4. User stories

### US-01: Обрати мову для вивчення

**As a** learner
**I want** обрати, яку мову вивчати (польська, англійська, німецька, нідерландська)
**So that** я вчу саме ту мову, що мені потрібна, а не лише польську

### US-02: Перемкнути активну мову

**As a** learner
**I want** перемикати активну мову серед тих, що я вивчаю
**So that** я можу вести кілька мов і повертатися до кожної

### US-03: Вести окремий прогрес на кожну мову

**As a** learner
**I want** щоб word status, повторення й daily new words limit рахувалися окремо для кожної мови
**So that** результати однієї мови не змішуються з іншою

### US-04: Почати нову мову з порожнього стану

**As a** learner
**I want** почати нову мову й побачити зрозумілий початковий стан
**So that** я розумію, з чого починати, коли слів цією мовою ще не вивчено

### US-05: Вчити слово з вимовою й формами активної мови

**As a** learner
**I want** бачити вимову, приклади й форми, властиві саме активній мові
**So that** підказки відповідають мові, яку я вивчаю, а не польській

### US-06: Повідомити про неточність у активній мові

**As a** learner
**I want** надіслати content report до слова активної мови
**So that** контент саме цієї мови покращується, і я бачу результат

### US-07: Готувати й схвалювати контент кожної мови окремо

**As a** content editor
**I want** готувати й схвалювати словник кожної мови окремо тим самим методом
**So that** кожна мова має перевірений контент, а мови не змішуються в черзі розгляду

## 5. Acceptance criteria

**Загальні правила, на які посилаються AC:**

- **Активна мова** — target language, у якій learner наразі займається; екран «Сьогодні», заняття, словник і налаштування показують стан саме активної мови. Learner може вивчати кілька target languages одночасно, але активна в кожен момент одна.
- **Окремий облік на мову** — для кожної target language, яку вивчає learner, word status слів, графік повторень, daily new words limit, облік дії «Вже знаю» та base course рахуються незалежно; дія в одній мові ніколи не змінює облік іншої.

### AC-01 (US-01) — happy path

**Given** learner ще не вивчає англійську, а для англійської є щонайменше одне схвалене слово
**When** learner обирає англійську
**Then** тренер починає вести англійську для цього learner окремо — з власним обліком нових слів у межах daily new words limit і власними word status — і показує екран «Сьогодні» англійської з першим заняттям

### AC-02 (US-01) — error

**Given** learner обирає target language, для якої ще немає жодного схваленого слова
**When** learner підтверджує вибір
**Then** тренер не починає навчання цією мовою, пояснює, що мова поки недоступна, і лишає поточну активну мову без змін

### AC-03 (US-02) — happy path

**Given** learner вивчає польську й англійську
**When** learner перемикає активну мову на англійську
**Then** екран «Сьогодні», заняття, словник і налаштування показують стан англійської, а весь облік польської лишається незмінним і доступним після зворотного перемикання

### AC-04 (US-02, US-03) — cross-context

**Given** learner має незавершену session однієї мови
**When** learner перемикає активну мову на іншу й починає заняття нею
**Then** session першої мови лишається незавершеною й доступною для продовження тієї самої доби learner, відповіді кожної мови зараховуються лише до обліку своєї мови, і жодна картка не переноситься між мовами

### AC-05 (US-03) — domain invariant

**Given** learner вивчає дві мови, і в одній вичерпано daily new words limit поточної доби learner
**When** learner займається другою мовою
**Then** друга мова має власний окремий облік daily new words limit, а word status, графік повторень і облік дії «Вже знаю» рахуються незалежно для кожної мови

### AC-06 (US-03) — domain invariant

**Given** кожна target language має власний base course зі схвалених лем
**When** тренер добирає нові слова для заняття активної мови
**Then** він бере леми лише з base course цієї мови в її власному порядку, і завершення курсу однієї мови не впливає на доступність нових слів іншої

### AC-07 (US-04) — happy path

**Given** learner щойно почав вивчати мову й ще не має жодного слова цієї мови в обліку
**When** learner відкриває екран «Сьогодні» цієї мови
**Then** тренер показує зрозумілий початковий стан і пропонує перші нові слова в межах daily new words limit, не показуючи лічильників прогресу інших мов

### AC-08 (US-05) — domain invariant

**Given** активна мова має власну вимову, приклади й словоформи
**When** learner бачить картку слова чи вправу пригадування цією мовою
**Then** підказка, приклад, прийняті варіанти відповіді й пошук за формами відповідають саме активній мові, а не польській, і нормалізація відповіді застосовує правила цієї мови

### AC-09 (US-06) — cross-context

**Given** learner вивчає кілька мов і бачить слово активної мови з неточністю
**When** learner надсилає content report
**Then** повідомлення прив'язується до запису саме активної мови й потрапляє в чергу розгляду цієї мови, не змінюючи контент інших мов

### AC-10 (US-03) — authorization

**Given** двоє learner вивчають ту саму мову
**When** один learner відкриває свій прогрес або словник цієї мови
**Then** він бачить лише власні word status і результати; прогрес іншого learner у будь-якій мові йому недоступний і ніде не відображається

### AC-11 (US-07) — cross-context

**Given** content editor розглядає content reports
**When** надходять повідомлення різними мовами
**Then** черга розгляду відокремлює повідомлення за мовою, і схвалення чи відкат зміни застосовується лише до словника тієї мови, якої стосується повідомлення

### AC-12 (US-01) — domain invariant

**Given** learner уже вивчає англійську
**When** learner повторно обирає англійську (через застаріле посилання, другу вкладку чи повторне натискання)
**Then** тренер не починає вести її вдруге й зберігає наявні word status, історію та облік нових слів цієї мови без змін

## 6. Non-functional requirements

| Aspect | Target | Measurement |
|---|---|---|
| Latency p95 відкриття «Сьогодні» активної мови | ≤ 1 500 ms | клієнтська телеметрія, час від запуску до рендера екрана |
| Latency p95 перемикання активної мови | ≤ 1 500 ms | час від вибору мови до рендера «Сьогодні» нової мови, клієнтська телеметрія |
| Latency p95 оцінки відповіді | ≤ 500 ms | серверна метрика часу від надсилання відповіді до результату |

| Ізоляція прогресу | 0 відповідей, зарахованих не до своєї мови | інтеграційний тест перемикання мови + щоденна звірка журналу відповідей за мовою |
| Availability | 99.5% | місячне SLO-вікно |

## 6.1 Security / privacy

- **Data classification:** confidential — тренер зберігає ідентичність і навчальну історію конкретних людей, тепер для кількох мов.
- **Personal data touched:** нових категорій персональних даних фіча не додає — прогрес на кожну мову належить до тих самих категорій, що й у reference ([personal-trainer-mvp §6.1](../personal-trainer-mvp/PRD.md)): word status, історія відповідей, текст content report. З'являється лише ознака мови при кожному обліковому записі прогресу й кожному content report (не персональні дані).
- **AuthZ/AuthN impact:** learner ідентифікується за перевіреною Telegram-ідентичністю; облік прогресу кожної мови обмежений власником-learner так само, як у reference. Роль content editor поширюється на чергу розгляду кожної мови окремо; нових authz-меж фіча не вводить, лише розмежовує наявні за мовою.
- **Abuse cases:**
  - Доступ до чужого прогресу (зокрема в іншій мові): тренер приховує існування даних іншого learner, а не повідомляє про заборону (AC-10).
  - Доступ до чужої мовної черги розгляду: content editor бачить і змінює лише словник тієї мови, якої стосується повідомлення (AC-11).
  - Спам content reports: наявний добовий ліміт повідомлень на learner (reference AC-46) застосовується до повідомлень активної мови; розмежування за мовою не збільшує сукупного ліміту на learner.
- **Security review:** успадковує verdict reference-фічі ([personal-trainer-mvp §6.1](../personal-trainer-mvp/PRD.md)); окремих нових PII-полів чи authz-меж немає. Security Lead підтверджує на review PRD, що розмежування за мовою не послаблює ізоляцію прогресу.

## 7. Metrics / KPIs

- **Частка непольської мови** — частка active learners, що мають активну target language з групи EN/DE/NL із щонайменше однією опрацьованою карткою. baseline: 0 (нова фіча), target: ≥ 30% за квартал після релізу ([idea-brief §13](./idea-brief.md#13-recommendation), Approach C).
- **Утримання по мові** — частка learner, що повернулися до непольської мови щонайменше 3 активні дні на другому тижні після її старту (щоб вибір мови не маскував відтік). baseline: 0, target: ≥ 40%.
- **Активація нової мови** — частка learner, що почали вивчати нову мову й завершили перше заняття нею. baseline: 0, target: ≥ 60%.
- **Розподіл між мовами** (діагностичний) — частка active learners на кожній з EN/DE/NL окремо, щоб бачити, чи дають утримання німецька й нідерландська, а не лише англійська. baseline: 0, target: вимір без формального go/no-go.

## 8. Open questions

- [ ] OQ-1: Чи може learner задати різний daily new words limit для кожної мови окремо, чи всі мови успадковують один спільний ліміт? Окремий облік на мову вже вирішено (інтерв'ю, AC-05); відкрите лише, чи ліміт редагується незалежно. Default зараз: один спільний ліміт learner застосовується до кожної мови окремо. — owner: Viacheslav Melnichenko, due: before architecture-design
- [ ] OQ-2: Як саме відбувається перемикання активної мови в інтерфейсі (окремий екран вибору, перемикач на «Сьогодні») і де learner додає нову мову? Поведінка обліку вже зафіксована (AC-03, AC-04); відкрите лише UI-розміщення. — owner: Viacheslav Melnichenko, due: before architecture-design
- [ ] OQ-3: Чи learner лишається однією сутністю з окремим обліком на кожну мову, чи моделюється як окрема одиниця на пару learner+мова? Це рішення про форму моделі даних. Default зараз: один learner з окремим обліком на кожну мову. — owner: Tech Lead, due: before architecture-design
- [ ] OQ-4: Що стається при одночасній роботі з 2+ мовами у різних вкладках (паралельні активні session різних мов, перемикання посеред заняття)? Поведінку перемикання задає AC-04; відкрите — розв'язання конкурентних змін у різних вкладках. — owner: Tech Lead, due: before architecture-design
- [ ] OQ-5: Чи узагальнюється звірка відповіді й генерація словоформ на німецьку та нідерландську (рід `der/die/das`, `de/het`, капіталізація іменників, складені слова)? Default зараз: повний аналог на кожну мову (AC-08). — owner: Tech Lead, due: before architecture-design
- [ ] OQ-6: Чи має механіка «local equivalents» сенс для EN/DE/NL, чи вона польсько-специфічна? Default зараз: опційно на кожну мову, лише де є усталені місцеві відповідники. — owner: Viacheslav Melnichenko, due: before architecture-design
