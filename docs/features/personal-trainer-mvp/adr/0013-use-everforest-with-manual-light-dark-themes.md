# 0013 — Використовувати Everforest із ручним вибором світлої та темної теми

## Контекст

Початковий SAD передбачав компоненти Telegram UI та кольори лише з theme params. Користувач запросив власну дизайн-систему з двома приглушеними темами й 2026-11-01 прийняв Everforest без зауважень після порівняння з Rosé Pine та Catppuccin.

## Рішення

- Використовувати затверджену адаптацію Everforest із [design-system.md](../design-system.md) і [theme-tokens.json](../design/theme-tokens.json). Це джерело семантичних кольорів; попередня вимога SAD про виключне успадкування кольорів Telegram замінена.
- Залишити React, TypeScript, Vite та Telegram UI kit за [ADR-0002](0002-build-mini-app-as-react-spa-served-by-aspnet-core.md). Компоненти, включно з modal/portal, підключити до спільних токенів продукту.
- Надати рівно два варіанти теми: «Світла» та «Темна». Ручний вибір застосовується негайно й зберігається локально за ключем `constant-learning.theme.v1`; зміни API та схеми БД не потрібні.
- До ручного вибору брати схему Telegram, потім ОС, далі світлу. Збережений вибір застосовувати до першого видимого рендера. Недоступність сховища не повинна блокувати поточний запуск; некоректні значення ігнорувати.
- Синхронізувати фон і шапку оболонки Mini App через підтримувані Telegram API з перевіркою версії. Тема всього Telegram не змінюється.

## Наслідки

Інтерфейс має сталу палітру незалежно від користувацьких кольорів Telegram. Потрібні адаптер UI kit, локальні перевірки обох тем і перевірка ручного пріоритету. На іншому пристрої вибір не синхронізується. Макет із порівняння палітр є демонстраційним; затверджені токени й поведінка не означають, що вже реалізовано екрани.

Виконавці: [T34](../tasks/T34-miniapp-skeleton.md) — провайдер, токени та компоненти; [T41](../tasks/T41-ui-settings.md) — перемикач; [T35](../tasks/T35-ui-onboarding.md)–[T42](../tasks/T42-ui-editor.md) — використання дизайн-системи. AC-58 задає приймання, перевірки описані в [test-plan.md](../test-plan.md).
